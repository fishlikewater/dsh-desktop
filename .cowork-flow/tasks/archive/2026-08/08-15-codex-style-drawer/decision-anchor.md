# Decision Anchor

## 目标
参考 Codex 桌面「已安排」实测设计（列表页 + 右上「创建」按钮 + 点击任务行打开右侧详情抽屉，含立即运行/暂停/编辑/删除/关闭与配置展示），把任务面板重构为"全宽列表 + 按需详情抽屉"，建议卡片带描述文字，列表行简化为只留开关。

## 验收标准
- [ ] AC-001: 面板布局改为全宽列表，右上角「创建」黑色胶囊按钮；常驻右侧表单栏移除。
- [ ] AC-002: 点击任务行打开右侧详情抽屉（约 360px，可关闭）：状态徽标、任务名、指令/提醒文案正文、配置列表（计划/动作/聚焦）、下次触发、上次触发。
- [ ] AC-003: 抽屉操作按钮：立即运行（test_task）、暂停/启用（toggle_task，文字随状态切换）、编辑（切表单）、删除（confirm）；操作后刷新。
- [ ] AC-004: 「创建」与「编辑」共用抽屉内表单（现有字段：名称/计划/动作/文案/聚焦/指令/预览/取消）；保存成功关抽屉刷新；Esc 退出编辑。
- [ ] AC-005: 列表行简化为：开关 + 时钟图标 + 名称 + 计划/动作 + 下次触发；行内测试/编辑/删除按钮移除（收进抽屉）。
- [ ] AC-006: 建议卡片每项增加描述文字行；点击行为保持"填入表单 + 打开创建抽屉"。
- [ ] AC-007: 空状态、筛选、搜索、排序行为不回归；`cargo test --release` 12 例全绿；`cargo build` 通过；JS 语法与 id 一致性检查通过。

## 被拒方案
- **Codex 式对话创建（自然语言引导）**: 拒绝原因——对话式创建依赖模型解析自然语言（Codex 用模型工具 schedule_create 落库），壳层无此执行链；表单是壳层能力范围内最直接的创建方式。
- **持久化运行历史列表（Codex 有"运行历史记录"）**: 拒绝原因——需要新增数据结构与持久化（recent_runs），属数据层范围膨胀；当前抽屉展示 next/last 触发已覆盖核心信息，历史列表留作后续迭代。
- **通知策略多级（所有运行/仅失败/从不）**: 拒绝原因——需后端通知策略字段与失败检测，超出本次 UI 对齐范围。

## 关键假设
- Codex 桌面「已安排」界面设计已通过实测截图采集（列表页、详情抽屉字段与按钮、创建入口、建议卡片结构），本次仅做布局与交互形态对齐，不复制其对话式创建。
- 后端 `list_tasks`/`test_task`/`toggle_task`/`delete_task`/`save_task` 已提供全部所需能力，后端零改动。
- 面板形态约束不变：覆盖右侧内容区、左侧 DSH 侧边栏可见（280px 偏移）。

## 范围边界
- 范围内: 全宽列表、右上「创建」按钮、右侧详情抽屉（查看/表单双模式）、行内按钮收进抽屉、建议卡片描述、文案对齐、空态引导。
- 范围外: 对话式创建、运行历史持久化、通知策略选项、模型选择（headless 不支持）、后端任何改动。
