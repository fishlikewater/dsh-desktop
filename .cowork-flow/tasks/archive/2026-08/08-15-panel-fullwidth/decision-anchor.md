# Decision Anchor

## 目标
修复用户反馈两问题：
- 问题 1：DSH GUI 侧边栏收起时，打开定时任务面板左侧留白（面板固定 left:280px 与实际 rail 56px 不匹配，露出被截断的 GUI 内容）。
- 问题 2：面板打开时点击「收起侧边栏」按钮误退出任务界面（左侧透明拦截层 #tasks-shield 把所有点击当作"退出面板"）。

## 验收标准
- [ ] AC-001: 移除 #tasks-shield 拦截层；面板打开时 DSH 侧边栏（含收起/展开按钮）完全可操作，点击不再退出面板。
- [ ] AC-002: 面板默认全宽覆盖（left:0），无论 GUI 侧边栏展开/收起都无左侧留白。
- [ ] AC-003: 面板头部「侧边栏」切换升级为三档：全宽 / 显示侧边栏（展开 280px）/ 显示侧边栏（收起 56px）；选择持久化 localStorage，重开面板套用。
- [ ] AC-004: 退出面板途径：✕ 按钮 / Esc / 标题栏时钟按钮 / 托盘菜单（均正常）。
- [ ] AC-005: 回归：JS 语法、DOM id 一致性通过；渲染预览（全宽/展开/收起三态）无布局问题；cargo build 通过；重新打包成功。

## 被拒方案
- **保留 shield + 手动两档按钮（现状）**: 拒绝原因——用户实测反馈拦截层误退（问题 2 未解决），手动按钮不够自动（问题 1 未解决）。
- **自动检测侧边栏状态**: 拒绝原因——DSH GUI 侧边栏状态在 zustand 内存 store（源码确认无 localStorage/文件持久化），跨域 iframe 无法读取；全宽默认从根上消除对侧边栏状态的依赖。
- **面板打开时同步模拟点击 GUI 收起按钮**: 拒绝原因——需要控制 DSH GUI（无此通道），且会改变用户 GUI 状态。

## 关键假设
- 全宽默认不违背用户"保留侧边栏"诉求：改为三档可切换（默认全宽，需要时一键显示侧边栏），比留白更优。
- DSH GUI 侧边栏：展开默认 280px、收起 rail 56px（已核实源码 computeColumns）。

## 范围边界
- 范围内: 移除 shield、面板三档侧边栏模式（全宽/280/56）、退出途径保持、重新打包。
- 范围外: 自动感知侧边栏状态、GUI 侧边栏宽度拖拽联动、其他面板布局改动。

## 验证命令
- node --check（抽取 JS）
- 渲染预览三态截图 + 视觉分析
- cargo build
- npm run build（重新打包）
